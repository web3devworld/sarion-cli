# Owner-controlled Ed25519 release signing

No release key was generated by the agent. Actual signing is pending a designated
owner key, reviewed source commit and explicit distribution authorization.
Ephemeral fixture keys qualify tooling only. Signing does not authorize publishing.

## Owner key generation and custody (Linux/macOS operator)

Run personally on the owner-controlled signing host, outside all repositories,
build directories and bundles. OpenSSL prompts for a strong encryption passphrase;
store it in the owner's password manager, separately from the encrypted key.
Do not put a passphrase in a command argument, environment variable or log.

```sh
set -euo pipefail
umask 077
mkdir -p "$HOME/.config/sarion-release-keys"
chmod 700 "$HOME/.config/sarion-release-keys"
# Refuse to overwrite an existing operator identity.
test ! -e "$HOME/.config/sarion-release-keys/operator-ed25519.pem" || exit 1
test ! -e "$HOME/.config/sarion-release-keys/operator-ed25519-public.pem" || exit 1
openssl genpkey -algorithm ED25519 -aes-256-cbc \
  -out "$HOME/.config/sarion-release-keys/operator-ed25519.pem"
chmod 600 "$HOME/.config/sarion-release-keys/operator-ed25519.pem"
openssl pkey -in "$HOME/.config/sarion-release-keys/operator-ed25519.pem" \
  -pubout -out "$HOME/.config/sarion-release-keys/operator-ed25519-public.pem"
openssl pkey -pubin -in "$HOME/.config/sarion-release-keys/operator-ed25519-public.pem" \
  -outform DER | openssl dgst -sha256
```

Record the 64 lowercase hexadecimal SPKI DER SHA-256 fingerprint in the owner's
release register. Securely back up the encrypted private key and separately held
unlock material under the owner's recovery policy. Keep the signing host/session
restricted. Do not upload the key to GitHub, copy it into a build, send it in chat,
or automatically replace a lost key. Lost/compromised keys require an explicit
rotation and independently authenticated trust update.

Only the public key and fingerprint are distributable. macOS/Linux mode checks
are enforced by the signing tool. Windows recipients can verify/install with Node;
the qualified signing procedure above uses the operator's Unix host with OpenSSL.
No native binary/notarization or Windows private-key ACL qualification is claimed.

## Review, sign and independently verify

Build twice from the reviewed exact client SHA using its committed lockfile,
Node 24.21.0 and npm 12.2.2; compare hashes. Clear inherited legacy signing env.
Inspect package, SBOM, provenance, licenses and manifest. Do not claim a dirty
working tree or a source-commit environment override as accepted provenance.

```sh
unset SARION_SIGNING_KEY_FILE SARION_SOURCE_COMMIT
git status --porcelain  # must be empty for the actual release build
npm ci --ignore-scripts
npm run build
npm run pack:release
# Compare provenance.sourceCommit with the separately reviewed full client SHA.
node scripts/sign-release.mjs /private/reviewed-bundle \
  "$HOME/.config/sarion-release-keys/operator-ed25519.pem" \
  /trusted/operator-ed25519-public.pem SPKI_SHA256 REVIEWED_CLIENT_SHA
node scripts/verify-release.mjs /private/reviewed-bundle \
  /trusted/operator-ed25519-public.pem SPKI_SHA256
```

Substitute the operator-confirmed fingerprint and reviewed 40-character client
SHA; the tools reject a mismatch. The signing process calls OpenSSL without
shell interpolation; encrypted-key unlocking prompts at the owner's terminal.
For a secure password-manager pipe only, append `--passphrase-stdin` to the
sign command; the password manager writes the passphrase directly to stdin.
Never use literal `echo PASSPHRASE`, `-passin pass:...`, shell tracing or a
passphrase environment variable. The script never generates keys or uploads.

The signer validates package size/hash, mandatory SBOM/provenance hashes, reviewed
source SHA, Ed25519 public-key type and pinned fingerprint. It verifies the new
detached signature against that key before installing manifest.sig. Verification
authenticates manifest bytes before trusting package/evidence fields. The
manifest transitively authenticates the package, SBOM and provenance; the latter
is not represented as a separate SLSA attestation.

Ship manifest.json, manifest.sig, package, SBOM/provenance, installer and these
reviewed verification scripts. Regenerate SHA256SUMS after signing. Source review
must establish the installer/verifier independently; do not trust replacement
verification code merely because it arrived alongside an untrusted package.

## Public-key trust distribution and installation

Owner sends the public PEM through the approved internal channel and confirms its
SPKI SHA-256 fingerprint through a separate authenticated channel (for example,
the existing owner release register plus a direct operator verification). The
recipient stores it in a trusted location outside the delivered bundle and pins
the fingerprint. Never accept a bundled public key as its own trust anchor.
Record key fingerprint, package hash, source SHA, audience and release approval.

```sh
node scripts/verify-release.mjs /offline/bundle /trusted/operator-public.pem SPKI_SHA256
SARION_RELEASE_PUBLIC_KEY=/trusted/operator-public.pem \
  node scripts/install.mjs /offline/bundle "$HOME/.local"
```

Windows PowerShell uses the same Node verifier and trusted public key:

```powershell
node scripts/verify-release.mjs C:\offline\bundle C:\trusted\operator-public.pem SPKI_SHA256
$env:SARION_RELEASE_PUBLIC_KEY='C:\trusted\operator-public.pem'
node scripts/install.mjs C:\offline\bundle "$env:LOCALAPPDATA\Sarion"
```

Existing offline installation uses --offline --ignore-scripts --no-audit --no-fund.
Preserve credentials, recovery journals, receipts and checkpoints on upgrades or
rollback. Unsigned candidates stay private and are refused by the installer.
